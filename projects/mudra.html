MUDRA+

Sign two or three glosses, pick a candidate sentence, and the phone speaks it into a call. Hand geometry for recognition, a small local LLM only for unseen sequences — no server, no API key, no account.

Design rationale

Fewer signs per sentence

Recognising an n-sign sentence succeeds with probability ≈ pⁿ. The architecture attacks both terms: shorten the signed key (autocomplete does the rest) and keep p high with a small, well-separated vocabulary plus a rejection threshold that answers UNKNOWN instead of guessing.

Survival probability at per-sign accuracy p = 0.95 · p = 0.90. A model of the failure mode, not a measurement.

Why no trained classifier in the live path

A classifier’s output layer is fixed to its training vocabulary. Adding one sign means data collection, retraining, re-export and shipping a new model. Template geometry lets a user record a new sign in about a second and use it on the next frame.

System architecture

Hold-to-confirm

A guide circle fills over the hold duration; a cooldown forces the hand to visibly re-form before the same gloss can fire again. On the call screen a detection zone restricts matching to hands held at sign height.

Glosses accumulate

Consecutive repeats of the same held sign are de-duplicated. A short key like ME NEED METFORMIN is enough to retrieve or generate a whole sentence.

["ME", "NEED", "METFORMIN"]

Seen? Remember. New? Compose.

An exact repeat returns from memory; a sequence whose candidates you chose before returns from sentence memory. Only unseen sequences wake the 3B model — which also keeps the phone cool under camera load.

sentenceMemory.get() → miss llm.complete() 1. I need one strip of Metformin, please. 2. I need Metformin. 3. Do you have Metformin?

The confirmation gate

Prompts ask for multiple candidates because a gloss sequence is genuinely ambiguous. Output is a candidate, never an action — also the guard against a hallucinated sentence.

▶ 1. I need one strip of Metformin, please. 2. I need Metformin. [ pick ] [ edit ] [ discard ]

Speakerphone or LAN relay

Android has no public API to inject audio into a cellular call, so output is acoustic coupling or a LAN relay to a second phone that speaks and streams a transcript back.

Failure behaviour: ids are assigned in RAM so a confirmed phrase is queryable before SQLite has heard of it (write-behind). A corrupt or full DB flips to memory-only and notifies the app; warm-up skips corrupt rows; malformed recogniser output is a returned value, never an exception; capacity is bounded with least-used eviction and pinned entries are never evicted.

Scope, honestly

Autocomplete, not translation

MUDRA+ is an autocomplete for a signer’s own recurring phrases. Interpretation is a human skill and this does not attempt it — the person confirms every sentence. The demo vocabulary is a handful of bundled single-hand static poses (GO, HOME, I, LEFT, PARK, REACH, RIGHT, WHERE) plus whatever the user records; two-handed and motion signs are not implemented. The next step is evaluating ergonomics with signers.
