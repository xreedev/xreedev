The idea

From a sentence to an installed app

Most “AI app builders” need a backend and a deploy step. PocketForge’s trick is that the service worker is the server: generated apps live in IndexedDB and are served at same-origin URLs the browser treats as installable PWAs.

System architecture

Three runtime files and a static host

Layout: index.html (landing), app/ (the builder PWA), sw.js and pf-shared.js (service worker + shared IndexedDB and storage helpers, loaded by both the window and the worker via importScripts).

◌

One shared module

pf-shared.js exposes the IndexedDB wrapper (all/get/put/del), served-HTML builder, manifest builder and storage shim to both contexts.

⚿

Key never in the repo

The API key is pasted into Settings and kept in the browser’s localStorage; requests carry it as X-API-Key. The Render instance may need up to a minute to wake.

⌂

Offline first

The builder shell is cached (pocketforge-v1); generated apps work offline once installed.

Lifecycle

Describe → Generate → Preview → Edit → Install

Click a step.

Prompt + imported files + options

A strict system prompt asks for one self-contained index.html: no CDNs, fonts, remote images or network requests; vanilla JS; phone-first; state in localStorage; source files embedded as initial data — never inventing facts not in the material.

system: “Output ONE self-contained index.html… Nothing external… works fully offline.”

LLM call with continuation

If the model stops for length, the client re-sends the transcript and asks it to continue — up to four passes — and stitches the output. extractHtml trims to a valid document and repairs a missing close tag.

pass 1 finish_reason: length pass 2 “Continue exactly where you stopped.” pass 2 finish_reason: stop

Sandboxed iframe

The generated HTML is shown in an iframe with a restrictive sandbox (allow-scripts allow-forms allow-modals allow-popups allow-downloads), using srcdoc; inside it storage falls back to memory.

<iframe sandbox="allow-scripts …" srcdoc="…generated app…">

Ask for changes

Follow-up requests go through the same llm() path with the conversation history, producing a revised document that replaces the stored project.

you: “make the cards green, add a search box” → new html → IndexedDB → preview refresh

Own URL, own manifest, own icon

Install opens /p/<id>/, served by the service worker from IndexedDB with a generated manifest and canvas-drawn icons; a floating “Install app” button handles beforeinstallprompt. Or export a host-anywhere .zip.

GET /p/k3x9/ → servedHtml(project) GET /p/k3x9/manifest.webmanifest GET /p/k3x9/icon-512.png

Isolation, honestly

What the namespace shim does — and doesn’t

All generated apps share the PocketForge origin. Each gets a localStorage namespace (pf:<id>:) by redefining window.localStorage, and falls back to in-memory storage inside the sandboxed preview.
