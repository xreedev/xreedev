The problem

Thousands of photos, no structure, reports easy to exaggerate

NGOs and volunteers photograph drain cleaning, tree planting, road repair — scattered across phones and chat groups. When a funder asks what changed, someone hunts for before/after shots by hand and the resulting reports are hard to verify.

System architecture

Provider-isolated, schema-strict, traceable

All AI provider code lives in gt/ai_provider.py — only Gemini is implemented but the interface is isolated. The model must return a strict JSON schema; if parsing fails, the raw output is stored, the asset is flagged needs_review and the pipeline continues.

1

Originals are sacred

Cloudinary stores the untouched original; the AI sees only a downscaled copy; every delivery variant is a logged transformation URL.

2

Everything AI is labelled

Captions, tags, signals and summaries carry “AI-suggested”, the model name and the raw output.

3

SQLite + numpy

Plain sqlite3 tables and numpy cosine similarity — no vector DB to deploy. Streamlit multipage UI.

Pipeline

Store originals, place them in time and space

Every photo goes to Cloudinary untouched, grouped by project. EXIF gives capture date + GPS. If EXIF is missing the asset is flagged rather than guessed.

asset kochi-before-01.jpg exif.time missing ⚑ missing date exif.gps missing ⚑ missing GPS

Vision model describes; search by meaning

A factual caption, activity type, visible signals (standing water, litter, fresh asphalt…) and tags — all labelled AI-suggested. Embeddings of caption + tags power semantic search with a “why it matched” explanation; without a key it falls back to labelled keyword search.

query: “exposed wiring near drain” #1 Kakkanad before 0.83 caption + tag: exposed cable

Suggest pairs; a person decides

Candidate before/after pairs are scored; never auto-confirmed. Confirmed pairs open in a comparison slider.

score = 0.4·loc + 0.4·visual + 0.2·time loc: 1/(1+(d/scale)²) visual: cosine time: 1 if after later else 0 [ confirm ] [ reject ]

A report you can verify

Summary text is generated only from stored captions, tags, dates and confirmed pairs, with timeline, sliders and evidence table. Downloads as print-ready HTML; campaign cards add Cloudinary overlays.

Original URL, upload time, EXIF, analysis JSON, raw model output, model name, the full transformation chain and which pairs/reports used it.

Pair suggestion

Three weak signals beat one

Location uses a haversine distance with a rational falloff (1/(1+(d/scale)²)), visual uses embedding cosine, time rewards “after is later than before”. Missing data degrades gracefully (e.g. same project but no GPS scores 0.5 on location).

404020
location 0.4visual similarity 0.4time ordering 0.2
Why this shape: each factor is explained in the UI with its note (“312 m apart”, “embedding cosine 0.84”, “after is 4 days later”), so a reviewer can see why a pair was suggested before confirming it.
Responsible AI

Checks that run on every image

≈

Near-duplicate flag

16×16 difference hash (256 bits); pairs within a Hamming-distance limit are flagged. Falls back to caption/tag embedding cosine ≥ 0.97 when no pixel hash exists.

⚑

Missing / inconsistent metadata

Missing GPS, missing date, capture-after-upload.

☺

People warning + face blur

Assets with people are warned; Cloudinary face blur is applied on delivery.

✓

Human in the loop

Pairs are only suggestions; confirmed pairs are shown as a visible difference, never as a verified repair.
